# 0AMV 因子研究设计

## 目标

将 TradePilot 从只为 B1 策略服务的回测工程中分离出一套独立、可复现的市场因子研究能力。第一项研究检验两类 0AMV 技术特征对上证指数、深证成指及全市场未来涨跌家数的预测关系。

该能力回答“0AMV 是否具有稳定的预测信息”，而非回答“将其加入交易规则后能否盈利”。B1 条件事件研究、组合构建与交易成本回测不在本次范围内。

## 范围与边界

### 本次实现

- 建立 `python/factor_research/` 独立研究包，不修改现有 `python/backtest/` 的交易逻辑。
- 使用 `data/backtest_data/0AMV-260612.csv` 作为 0AMV 原始日线输入。
- 首次从腾讯财经拉取上证指数（`sh000001`）和深证成指（`sz399001`）日线，缓存到本地；只有显式 `--refresh` 才刷新缓存。
- 利用现有 `data/backtest_data/5m_price/<year>/*.parquet` 聚合得到全市场日收盘价，以计算未来上涨、下跌、平盘家数和上涨比例。
- 通过 YAML 配置运行研究，并产出 CSV、JSON 与 Markdown 报告。
- 为时序、标签、统计、缓存和端到端运行编写自动化测试。

### 不在本次实现

- B1/B2 事件研究、持仓与仓位调整、模拟交易、滑点或成本分析。
- Web API、Vue 页面、数据库、定时任务或在线实时研究。
- 对候选因子的因果解释或直接给出交易结论。

## 架构

```text
0AMV CSV ───────────────┐
指数 CSV 缓存/腾讯下载 ─┼─> 研究数据对齐 ─> 因子与标签 ─> 统计评估 ─> 报告与结果快照
股票 5 分钟 Parquet ───┘
```

研究包按单一职责分层：

- `data`: 读取、验证和对齐 0AMV、指数和全市场价格；管理指数缓存。
- `features`: 根据已知的 0AMV 历史计算技术特征。
- `labels`: 生成未来指数收益和未来市场广度标签。
- `evaluators`: 计算分位数组、相关性和年度稳定性。
- `reporting`: 序列化逐日观测、汇总表、元数据和 Markdown 报告。
- `run_experiment`: 解析命令参数、装配组件并管理单次实验目录。

现有 `TencentSource.fetch_kline_raw` 是指数下载的唯一复用入口；研究层不依赖 `TimingSignal`，以避免把现有仓位规则误当成因子定义。

## 数据口径与时序

### 数据源

| 数据 | 来源 | 本地位置 |
|---|---|---|
| 0AMV 日线 | 已有 CSV | `data/backtest_data/0AMV-260612.csv` |
| 上证指数 | 腾讯财经，缓存优先 | `data/factor_research_data/indices/sh000001.csv` |
| 深证成指 | 腾讯财经，缓存优先 | `data/factor_research_data/indices/sz399001.csv` |
| 市场广度 | 已有分钟 Parquet 聚合日线 | `data/backtest_data/5m_price/<year>/*.parquet` |

指数缓存包含标准列 `date, open, high, low, close, volume`，日期按交易日标准化。首次运行若缓存不存在则下载；缓存存在时不访问网络；`--refresh` 会重新下载并原子替换对应缓存。下载失败时，已有缓存可继续使用；不存在缓存则中止并报告原因。

### 因子定义

对每个交易日 `t`，仅使用 `t` 日及此前的 0AMV 收盘数据计算：

- 偏离度：`amv_ma_gap_N(t) = 0AMV(t) / SMA_N(t) - 1`，`N ∈ {5, 10, 20, 60}`。
- 动量：`amv_return_N(t) = 0AMV(t) / 0AMV(t-N) - 1`，`N ∈ {1, 3, 5, 10}`。

所有窗口由配置提供，默认值为上述集合。窗口历史不足的因子值为缺失，不作填充。

### 未来标签

对每个预测期 `h ∈ {1, 3, 5, 10}`：

- 指数前瞻收益：`close_index(t+h) / close_index(t) - 1`。
- 对每只股票：`close_stock(t+h) / close_stock(t) - 1`。
- 只纳入 `t` 与 `t+h` 均有有效收盘价，且起点收盘价大于 0 的股票。
- 个股收益 `> 0`、`< 0`、`= 0` 分别为上涨、下跌、平盘；市场标签记录 `advancers_h`、`decliners_h`、`unchanged_h`、`eligible_count_h` 和 `advance_ratio_h = advancers_h / eligible_count_h`。

标签中的 `t+h` 始终是当前数据集合中第 `h` 个后续交易日，而不是自然日。缺少未来数据的末尾样本保留因子值，但相应标签为空且不得进入该标签的统计。

本研究的因子在收盘后才可完整计算，最早可用于下一交易日的决策。报告必须明确此口径，防止将 `t` 日收盘信息误用于 `t` 日盘中交易。

## 评估方法

每个“因子 × 预测期 × 目标”独立使用标签非空的共同样本评估。

### 分位数组

默认将因子值等频分为五组（Q1 至 Q5）；相同数值导致无法可靠分组时，结果标记为样本或取值不足，不虚构组别。每组输出：样本数、目标均值、目标中位数、正值胜率。对收益和上涨比例目标，额外输出 Q5-Q1 差、组均值是否单调不减或单调不增。

### 相关性与稳定性

- 计算 Pearson 和 Spearman 相关系数及有效样本数。
- 以自然年度重复统计；报告每年相关方向、有效样本数和 Q5-Q1。
- 汇总全年份中方向一致的比例；年样本不足或分组失败须明确标记而非视为有效结论。

### 数据质量

报告数据日期交集、原始行数、各因子和标签的覆盖率、每个预测期的有效股票数描述统计，以及任一输入数据缺失或日期不匹配的告警。

## 配置、命令与产物

默认配置文件为 `python/config/factor_research_0amv.yaml`，至少包含：样本起止日期、数据路径、指数代码、因子窗口、预测期、分组数和输出根目录。

执行命令：

```bash
python -m python.factor_research.run_experiment \
  --config python/config/factor_research_0amv.yaml
```

可选 `--refresh` 用于更新指数缓存。每次执行写入唯一目录 `data/factor_research_runs/<run-id>/`：

```text
metadata.json
observations.csv
factor_summary.csv
report.md
```

- `observations.csv`：`date`、因子名称和值、两项指数前瞻收益、各预测期市场广度标签。
- `factor_summary.csv`：因子、预测期、目标、样本数、相关性、分位数组和年度稳定性指标。
- `metadata.json`：完整已解析配置、运行时间、输入文件 SHA-256、输入行数、代码 Git commit、Python 包版本及告警。
- `report.md`：数据质量、方法说明、完整统计表、年度稳定性和“结果不构成交易建议”的提示。

`run-id` 由 UTC 时间戳与已解析配置的短 SHA-256 组成，保证不同参数运行可区分。目标输出目录已存在时必须拒绝覆盖。

## 错误处理

- 缺少必需列、日期格式错误、重复日期、空输入、样本区间无交集或有效样本不足：抛出面向用户的错误并返回非零退出码。
- 指数拉取失败：有缓存时记录警告并继续；无缓存时停止。
- Parquet 文件缺失或损坏：记录具体文件并停止，不以不完整股票池伪造全市场广度。
- 单个因子或目标样本不足：保留本次运行，且在汇总和报告中标记为不可评估；不生成无意义相关系数。

## 测试策略

新建 `python/tests/factor_research/`，所有新生产行为先由失败测试定义。测试使用内存 DataFrame 和临时目录，不读取 25GB 的真实数据也不访问网络：

- 因子仅依赖当日及过去观测，滚动窗口不足时为空。
- 前瞻标签准确使用第 `h` 个后续交易日，且末尾数据为空。
- 广度计算正确排除缺失起点或终点价格，分别计数涨、跌、平并计算上涨比例。
- 指数缓存存在时不下载；刷新时下载并更新缓存；下载失败的缓存回退和无缓存失败均可验证。
- 分位数组、相关性、常数因子、样本不足和年度统计都有确定行为。
- 小型临时数据集可以端到端生成四种产物和完整元数据。

## 验收标准

1. 用户能只凭 YAML 和一条命令完成一项 0AMV 研究。
2. 同一份缓存与配置产生可追溯、不可覆盖的实验目录，并记录代码和输入指纹。
3. 报告分别展示 8 个默认 0AMV 特征对两项指数收益与市场广度的 `1/3/5/10` 交易日前瞻结果。
4. 研究层不调用策略交易、仓位控制或 `TimingSignal`。
5. 自动化测试证明没有前瞻因子计算，并覆盖数据标签、统计、缓存和端到端运行。
