# TradePilot 因子研究

把研究想法变成可检验的问题、可执行的编码计划，以及可复现的研究任务。项目约定以当前的 `docs/backtest-development.md`、`python/task_registry.py` 和 `python/research/` 中相近任务为准；不要假定旧研究脚本具有统一的输出格式。

## 明确研究问题

先检查可用数据与相关代码，再确认指标定义、信号产生时点、研究对象、样本区间，以及会影响结论的比较基准。**确定方案前，问清用户要统计哪些远期收益率**：未来多少个交易日或 K 线、从什么时点和价格起算、使用何种复权口径、统计绝对收益还是相对基准收益。用户尚未指定时，给出简洁的建议口径供选择；不要默默替重大歧义设默认值。将确定的收益定义写成公式，并说明哪些观测因未来数据不足而无法打标签。

## 建议并确认研究方法

说明待检验的假设，提出少量适合数据结构的研究方法，给出推荐及取舍。例如：离散信号适合事件研究或条件收益比较；连续因子适合分位数组和秩相关；全市场指标适合时间序列条件分析；多只证券构成的样本适合横截面比较。交代观测单位、对照基线、远期窗口重叠、样本数量、缺失值，以及按时间或市场状态分段的方式。

未来收益只能作为结果标签。时间 `t` 的指标和阈值只能使用 `t` 时已知的数据；预热历史与正式统计区间分开。研究宏观指标时，核对数据的公布和修订时间。相关性或统计显著性不能直接表述为因果关系。

让用户确定研究方法后再敲定编码计划。仅在资料可获得且与问题相关时引用书籍或其他材料；涉及精确论断时核对原文，不声称读过无法取得的资料。

## 计划、实现与验证

编码计划应写清数据输入及覆盖范围、因子和收益标签的定义、统计方法与诊断、代码位置、运行命令、产物和验收方式。方案确定后，在用户请求授权的范围内继续实现。可复用计算放在 `python/factors/`，实验逻辑放在 `python/research/<topic>/`；需要统一命令运行时，在 `python/task_registry.py` 注册任务。适用时使用 `./scripts/backtest.sh list research` 和 `./scripts/backtest.sh run research <名称> --start YYYYMMDD --end YYYYMMDD`。运行产物放在 `data/factor_research_runs/`；用户需要共享结论时，写到 `docs/factor-result/`。

用小型已知样例核对收益公式与时间对齐，再运行相关测试和一个有代表性的研究区间。检查样本数量、未来窗口不足而剔除的记录、输出文件及 `run_manifest.json`。报告结论时说明数据覆盖范围、局限，以及实现过程中变更的方法或数据口径。
